# NullCollectionDynamicCount Review

## Verdict
Not functionally correct for the null-collection scenario, and likely not what a user expects from a fixture named `NullCollectionDynamicCount`. The generated code does honor `[SerializeCollection(CountType = typeof(byte))]` for non-null lists, but it serializes `null` as a zero count and always deserializes zero back to `new List<Item>(0)`, so `Items == null` does not round-trip.

## Open questions / assumptions
- Assumed the fixture name is intentional and that preserving a meaningful distinction between `null` and empty collections matters more here than merely honoring the `byte` count width.
- If the intended contract is "count-prefixed nullable collections are canonicalized to empty on deserialize," then the top issue is an expectation mismatch rather than a generator bug.

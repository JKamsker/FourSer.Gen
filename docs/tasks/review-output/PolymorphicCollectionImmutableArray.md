## Performance opportunities
- Deserialize directly into an `ImmutableArray<IItem>` builder or other fixed-size backing store instead of `List<IItem>` + `ImmutableArray.CreateRange(...)`, which currently adds a staging collection and a second copy (`tests/FourSer.Tests/GeneratorTestCases/PolymorphicCollectionImmutableArray/PolymorphicCollectionImmutableArray.RunGeneratorTest.verified.txt:55-83`, `tests/FourSer.Tests/GeneratorTestCases/PolymorphicCollectionImmutableArray/PolymorphicCollectionImmutableArray.RunGeneratorTest.verified.txt:95-123`).
- The stream serializer currently does one `StreamWriter.WriteByte` call per element, even though the leaf payload serializers are empty in this case. Batching the discriminator bytes would materially reduce stream calls for large collections (`tests/FourSer.Tests/GeneratorTestCases/PolymorphicCollectionImmutableArray/PolymorphicCollectionImmutableArray.RunGeneratorTest.verified.txt:200-215`, `tests/FourSer.Tests/GeneratorTestCases/PolymorphicCollectionImmutableArray/PolymorphicCollectionImmutableArray.RunGeneratorTest.verified.txt:247-299`, `tests/FourSer.Tests/GeneratorTestCases/PolymorphicCollectionImmutableArray/PolymorphicCollectionImmutableArray.RunGeneratorTest.verified.txt:321-373`, `tests/FourSer.Tests/GeneratorTestCases/PolymorphicCollectionImmutableArray/PolymorphicCollectionImmutableArray.RunGeneratorTest.verified.txt:395-447`).
- If the generator keeps separate validation, combining type/null validation with packet-size calculation or the actual write pass would remove an extra full traversal over the immutable array (`tests/FourSer.Tests/GeneratorTestCases/PolymorphicCollectionImmutableArray/PolymorphicCollectionImmutableArray.RunGeneratorTest.verified.txt:29-39`, `tests/FourSer.Tests/GeneratorTestCases/PolymorphicCollectionImmutableArray/PolymorphicCollectionImmutableArray.RunGeneratorTest.verified.txt:134-171`, `tests/FourSer.Tests/GeneratorTestCases/PolymorphicCollectionImmutableArray/PolymorphicCollectionImmutableArray.RunGeneratorTest.verified.txt:186-223`).

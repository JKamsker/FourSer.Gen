# PolymorphicDefaultOption Review

## Verdict
Functionally correct for `tests/FourSer.Tests/GeneratorTestCases/PolymorphicDefaultOption/input.cs` and aligned with current repo expectations for default discriminators. The generated `Inventory` serializer writes the default `Shield` discriminator for empty or `null` single-type collections, derives `ItemType` from `ReadOnlyItems` rather than trusting the caller-provided property value, and deserializes the same wire shape back consistently. That matches the source model in `tests/FourSer.Tests/GeneratorTestCases/PolymorphicDefaultOption/input.cs:10-21` and the existing expectations encoded in `tests/FourSer.Tests/GeneratorTests.cs:240-275` and `tests/FourSer.Tests.Behavioural/Polymorphism/PolymorphicCollectionParityTests.cs:350-410`.

## Performance opportunities
- Cache the validated `ReadOnlyItems` discriminator once and reuse it. The current span path walks the buffered list to validate homogeneity at `tests/FourSer.Tests/GeneratorTestCases/PolymorphicDefaultOption/PolymorphicDefaultOption.RunGeneratorTest.verified.txt:257-292`, then reads the first element again to write `ItemType` at `:293-312`, then reads the first element yet again to choose the serialization switch at `:365-380`; the stream path repeats the same pattern at `:448-503` and `:556-571`.
- Drop the second list allocation on deserialization. `readOnlyItemsStaging` is already a `List<IItem>` suitable for the `IReadOnlyCollection<IItem>` property, so the extra copy at `tests/FourSer.Tests/GeneratorTestCases/PolymorphicDefaultOption/PolymorphicDefaultOption.RunGeneratorTest.verified.txt:148-149` and `:214-215` is pure allocation and copy overhead.
- There is a stream batching opportunity around the scalar headers. `Serialize(Stream)` emits separate `WriteByte`/`WriteInt32`/`WriteByte` calls for `ItemType`, `Items` count, and `Items` discriminator at `tests/FourSer.Tests/GeneratorTestCases/PolymorphicDefaultOption/PolymorphicDefaultOption.RunGeneratorTest.verified.txt:484-528`, plus another `WriteInt32` for `ReadOnlyItems` at `:550-556`; if this path gains scalar batching, those adjacent header writes could be coalesced to reduce stream call count.
- The same single-type validation logic for `Items` is emitted independently for span and stream at `tests/FourSer.Tests/GeneratorTestCases/PolymorphicDefaultOption/PolymorphicDefaultOption.RunGeneratorTest.verified.txt:226-255` and `:417-446`. That is more code-size duplication than runtime cost, but it is still redundant generated work that a shared helper or common plan shape could remove.

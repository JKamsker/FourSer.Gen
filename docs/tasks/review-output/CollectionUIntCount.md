# CollectionUIntCount Review

## Verdict
Partially correct. The generated code uses `uint` consistently for the collection count and should round-trip non-null values as expected, but it is not fully functionally correct or aligned with the documented null-handling contract because it silently normalizes unsupported null reference states.

## Findings
- Medium: `UIntCountTest.Cats` is serialized as `0` when it is `null`, then always deserialized as a new empty list, so `null` and `[]` are not distinguishable. See `tests/FourSer.Tests/GeneratorTestCases/CollectionUIntCount/input.cs:7`, `tests/FourSer.Tests/GeneratorTestCases/CollectionUIntCount/CollectionUIntCount.RunGeneratorTest.verified.txt:55`, `tests/FourSer.Tests/GeneratorTestCases/CollectionUIntCount/CollectionUIntCount.RunGeneratorTest.verified.txt:56`, `tests/FourSer.Tests/GeneratorTestCases/CollectionUIntCount/CollectionUIntCount.RunGeneratorTest.verified.txt:91`, `tests/FourSer.Tests/GeneratorTestCases/CollectionUIntCount/CollectionUIntCount.RunGeneratorTest.verified.txt:93`, `tests/FourSer.Tests/GeneratorTestCases/CollectionUIntCount/CollectionUIntCount.RunGeneratorTest.verified.txt:120`, and `tests/FourSer.Tests/GeneratorTestCases/CollectionUIntCount/CollectionUIntCount.RunGeneratorTest.verified.txt:122`. This also conflicts with the documented limitation that null reference values are not supported: `README.md:34`.
- Medium: `Cat.Name` silently collapses `null` to `string.Empty` instead of rejecting it or preserving it. The generated stream path writes a zero length for `null`/empty (`tests/FourSer.Tests/GeneratorTestCases/CollectionUIntCount/CollectionUIntCount.RunGeneratorTest.verified.txt:229` and `tests/FourSer.Tests/GeneratorTestCases/CollectionUIntCount/CollectionUIntCount.RunGeneratorTest.verified.txt:231`), and the shared string helpers/readers map zero length back to `string.Empty` (`src/FourSer.Gen/Resources/Code/StringHelper.cs:13`, `src/FourSer.Gen/Resources/Code/StringHelper.cs:25`, `src/FourSer.Gen/Resources/Code/StringHelper.cs:50`, `src/FourSer.Gen/Resources/Code/StreamReaderHelpers.cs:105`, `src/FourSer.Gen/Resources/Code/StreamWriterHelpers.cs:122`). That is another silent contract change relative to `README.md:34`.
